# Iteration 2 — Cosmos DB Shell demo

Cosmos DB Shell scripts for the **optimized two-container design**.
Same database name (`Build26DEM310`) as iteration 1, but the container
shape and partition keys are picked to match the access patterns.

## Folder contents

| File | What it does |
|------|--------------|
| `01-setup.cosmos.js` | Creates `CustomerOrders` (PK `/customerId`, type-discriminated docs) and `Products` (PK `/categoryId`) with a **tightened indexing policy** that only indexes the paths we filter or sort on. Seeds both containers. |
| `02-access-patterns.cosmos.js` | Runs P1–P4 against the new layout and prints `requestCharge` per step. Includes the **transactional batch** for P3. |
| `seed-data/CustomerOrders.json` | 210 docs (10 customers + 200 orders, type-discriminated, items embedded on order docs). |
| `seed-data/Products.json` | 50 product docs (PK `/categoryId`). |

The JSON files are regenerated by `src/sample-data/build_demo_shell.py`.

## Container layout

| Container        | Partition key | Document types | Notes |
|------------------|---------------|----------------|-------|
| `CustomerOrders` | `/customerId` | `customer`, `order` | Customer + all their orders live in one partition. P1 becomes a single-partition query; P3 becomes a transactional batch. |
| `Products`       | `/categoryId` | `product`           | P4 ("products in category") becomes a single-partition query. |

Indexing policy (both containers):

```json
{
  "indexingMode": "consistent",
  "automatic": true,
  "includedPaths": [
    { "path": "/customerId/?" }, { "path": "/type/?" },
    { "path": "/orderDate/?" },  { "path": "/status/?" },
    { "path": "/categoryId/?" }, { "path": "/price/?" }, { "path": "/rating/?" }
  ],
  "excludedPaths": [
    { "path": "/*" }, { "path": "/items/*" }, { "path": "/\"_etag\"/?" }
  ],
  "compositeIndexes": []
}
```

The `/items/*` exclusion is the big win — the embedded line items are
read with the order doc but never indexed, so writes stay cheap.

## How to demo

1. Open the Cosmos DB Shell against the **classic Windows emulator** or a
   real Cosmos DB account.
2. Paste `01-setup.cosmos.js` and run it.
3. Walk through `02-access-patterns.cosmos.js` block by block. Compare
   each `RU:` value with the iteration-1 (naive-a) equivalent — that
   delta is the whole point of the talk.
